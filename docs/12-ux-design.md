# 12 · UX 设计方案（移动优先 · 一比一还原规格）

> 适用范围：`:ui` 模块。本文是**设计定稿**，不是灵感收集。第 6 节起是可直接照做的实现清单。
> 所有尺寸单位 dp/sp，间距一律 8dp 基线。最小验证宽度 **320dp**。

---

## 1. 设计诊断：当前为什么"看不懂、不会用"

诊断来自代码实证，不来自猜测。

| # | 证据（文件 / 符号） | 用户的实际遭遇 |
|---|---|---|
| 1 | `AkeNavHost.kt:113` `startDestination = AkeRoute.CHAT_LIST` | 打开 App 就是对话页。但端侧模型没下载 ⇒ 发消息必然失败 |
| 2 | 全仓 grep `onboard / firstLaunch / welcome` → **无命中** | 没有任何首启引导。用户必须**自己发现**"模型"入口（它在 `HomeScreen` 底部三个小按钮里），才知道要先下 2.6GB |
| 3 | `strings.xml` `chat_runner_missing` = "对话主循环还没接线（ChatRunnerPort 在 Hilt 里没有绑定），这一页现在只能看历史消息。" | **开发者内部信息直接暴露给终端用户** |
| 4 | `AkeNavHost` 底栏四 tab：对话 / Agent / 任务 / 设置 | "Agent""任务"是陌生概念；而"任务"才是浏览器自动化主场，却与"对话"割裂成两个 tab |
| 5 | `HomeScreen.kt:79` 首屏 `Text("要它做什么？")` + `Button("开始执行")` | 首屏即浏览器自动化，无前置说明、无能力边界告知 |

**根因一句话**：App 假设用户已经知道「要先下载模型」「什么是 Agent」「任务是什么」。这个假设对第一次打开的人不成立，于是第一步就卡死，且**卡死时不告诉用户该去哪**（问题 1+2+3 叠加）。

**设计要解决的不是"好不好看"，是"第一次打开的人能不能走通第一步"。**

## 2. 信息架构重构

### 2.1 核心决策：把「模型就绪」提升为一级门控

现状把模型下载藏在设置深处。新架构把它提到**启动流程本身**：

```
启动
  │
  ├─ 模型未就绪 ──▶ 【模型门控页】(全屏，唯一可做的事)
  │                   说明 → 下载 → 进度 → 就绪
  │
  └─ 模型已就绪 ──▶ 【对话列表】(主场)
                        │
                        └─▶ 【对话页】
                                └─ 技能卡（浏览器任务在此触发，不再独立成 tab）
```

### 2.2 底栏：4 tab → 3 tab

| 旧 | 新 | 理由 |
|---|---|---|
| 对话 | **对话** | 主场 |
| Agent | **Agent** | 保留，但改名见 §2.3 |
| 任务 | ~~删除~~ | 浏览器任务降级为对话内的技能卡，不再独立成页 |
| 设置 | **我的** | 模型管理、云端后端、工具在此 |

**删除"任务"tab 的理由**：它是浏览器自动化的执行页，而现在用户在对话里下达网页任务即可，任务进度以技能卡形式内联在会话流中。独立成 tab 会让用户在"对话"和"任务"之间来回跳——两个入口做同一件事，是困惑的主要来源。

### 2.3 术语统一（消除行话）

| 现状用词 | 改为 | 出现在 |
|---|---|---|
| Agent | **助手** | 底栏、列表标题 |
| 任务 / TaskPhase / 步骤 | **执行中 / 已完成**（不出现"TaskPhase"） | 技能卡状态 |
| MCP / 能力 / 插件 | **工具** | 助手详情 |
| `ChatRunnerPort 未绑定` 等 | **删除或改写为用户语言** | 见 §5.4 |

## 3. 移动优先布局

### 3.1 断点与栅格

| 断点 | 宽度 | 列数 | 边距 | 说明 |
|---|---|---|---|---|
| **xs** | 320–359 | 4 | 16 | 最小验证宽度，单列 |
| **sm** | 360–599 | 4 | 16 | 主流手机，单列 |
| **md** | 600–839 | 8 | 24 | 大屏手机 / 小平板 |
| **lg** | ≥840 | 12 | 32 | 平板，列表+详情双栏 |

**默认单列**。≥600dp 时对话列表可用 `LazyVerticalGrid(columns = GridCells.Adaptive(minSize = 320.dp))`，但**对话页永远单列**（对话是线性流，双栏会割裂上下文）。

### 3.2 关键尺寸

| 元素 | 值 | 理由 |
|---|---|---|
| 触摸目标最小 | **48×48dp** | WCAG 2.2 Target Size (Minimum) 2.5.8 |
| 页面左右边距 | 16dp（≥600dp 时 24dp） | |
| 卡片间距 | 12dp | |
| 卡片圆角 | 16dp | |
| 按钮圆角 | 12dp | |
| 底栏高度 | 64dp + 系统手势区 | |
| 输入框最小高度 | 48dp，最大 120dp（超出滚动） | |
| 内容最大宽度 | ≥840dp 时 720dp 居中 | 防超宽行降低可读性 |

### 3.3 安全区

- 底栏必须处理 `navigationBarsPadding()`，避免手势条遮挡
- 输入法弹出时输入框不被遮挡：`imePadding()`
- 下载进度页禁止横竖屏切换导致进度丢失（`android:screenOrientation="portrait"` 或 `ViewModel` 持有进度）

## 4. 配色方案

### 4.1 主色：靛蓝 Indigo（50–900）

选它的理由：AI 类产品主流色相、在深色模式下对比度表现优秀、与既有的"信任蓝"语义兼容（不冲突），且能明确区分于"系统蓝"。

| Token | 色值 | 用途 |
|---|---|---|
| `primary-50` | `#EEF2FF` | 浅色容器底 |
| `primary-100` | `#E0E7FF` | 选中态底 |
| `primary-200` | `#C7D2FE` | 禁用态 |
| `primary-300` | `#A5B4FC` | 深色模式次要文本 |
| `primary-400` | `#818CF8` | |
| **`primary-500`** | **`#6366F1`** | **主色 · 按钮底 · 深色模式主色** |
| `primary-600` | `#4F46E5` | 浅色模式主色 · 按压态 |
| `primary-700` | `#4338CA` | 悬停/聚焦 |
| `primary-800` | `#3730A3` | |
| `primary-900` | `#312E81` | 深色容器底 |

### 4.2 语义色

| 语义 | Light | Dark | 用途 |
|---|---|---|---|
| 成功 / 已完成 | `#16A34A` | `#4ADE80` | 下载完成、任务成功 |
| 警告 | `#EA580C` | `#FB923C` | 敏感操作确认 |
| 错误 / 失败 | `#DC2626` | `#F87171` | 下载失败、推理失败 |
| 信息 | `#0D9488` | `#2DD4BF` | **"本机处理 / 数据不出机"徽标** |
| 中性强调 | `#0F172A` | `#F8FAFC` | 主文本 |

**青绿 `#0D9488` 专门承载"本地/离线/隐私"语义** —— 这是本产品与云端 AI 的唯一本质区别，值得一个专属色。凡出现"本机处理""数据不出机""离线可用"的地方，一律用这个色，形成稳定联想。

### 4.3 中性色（Slate）

| Token | Light | Dark |
|---|---|---|
| background | `#FFFFFF` | `#0B1120` |
| surface | `#F8FAFC` | `#131C31` |
| surface-variant | `#EEF2F7` | `#1E293B` |
| outline | `#CBD5E1` | `#334155` |
| on-surface | `#0F172A` | `#E8EDF5` |
| on-surface-variant | `#64748B` | `#94A3B8` |

### 4.4 与既有风险五色共存

`AkeTheme` 里已有 `RiskReadOnly/RiskPageMutating/RiskSensitive/RiskExternal/RiskForbidden`（绿/蓝/橙/紫/深红）。**保留不动**——它们是功能性的风险分级，且已被 `StepTimeline` 等组件使用。

⚠️ 冲突点：`RiskReadOnly` 是 `#2E7D32`（绿），与新语义"成功绿 `#16A34A`"色相接近。**裁决**：风险色只在**技能卡/步骤**里出现，语义色只在**状态徽标/按钮**里出现，两者不在同一组件混用。

### 4.5 深色模式

必须实现，且不是简单反色：
- 深色下 `primary` 用 `primary-500`（`#6366F1`）而非 `primary-600`，保证对深底的对比度
- 禁用纯黑 `#000000`（OLED 拖影），用 `#0B1120`
- 卡片用 `#131C31` 与背景 `#0B1120` 形成层次，不用分隔线

## 5. 核心流程设计

### 5.1 首次启动 → 模型下载（本设计的第一优先级）

**页面：模型门控页**（全屏，无底栏，无返回）

```
        [图标：本机芯片]
                          
     先把本地模型装好
                          
  阿客在你手机上运行，不联网也能用。
  首次需要下载一个 2.8 GB 的模型，
  之后所有对话都在本机完成。
                          
  ┌────────────────────────┐
  │ ✓ 数据不出手机          │   ← 青绿徽标
  │ ✓ 下载后可离线使用      │
  │ ✓ 仅首次需要下载        │
  └────────────────────────┘
                          
  ┌────────────────────────┐
  │      下载模型 (2.8 GB)  │   ← 主按钮，48dp 高
  └────────────────────────┘
                          
      需要 Wi‑Fi，约 5–10 分钟
```

**三条原则**：
1. **说清代价**：2.6GB、需 Wi-Fi、约多久、仅一次。不藏着。
2. **说清收益**：数据不出手机、可离线。用青绿色强化。
3. **只有一个按钮**：不给"跳过"。跳过 = 进到一个用不了的对话页 = 复现当前 bug。

### 5.2 下载中（进度页）

| 元素 | 规格 |
|---|---|
| 进度条 | `LinearProgressIndicator`，高 8dp，圆角 4dp |
| 百分比 | 32sp / Bold，居中大数字 |
| 速度 + 剩余 | "12.4 MB/s · 还剩约 3 分钟" |
| 状态文案 | "正在下载，请勿关闭应用" |
| 按钮 | **暂停 / 继续**（48dp，次要按钮），**取消**（文本按钮） |
| 失败态 | 明确原因 + "重试"；**不许只说"下载失败"** |

⚠️ **不可用 Wi-Fi 时**：提前拦截，显示"当前不是 Wi‑Fi，下载会消耗 2.6GB 流量" + 两个按钮（仍要下载 / 去连 Wi‑Fi）。

### 5.3 就绪 → 对话

模型就绪后**自动进入对话列表**，不要求用户点返回。下载完成页停留 1.2s 展示"✓ 模型已就绪"，然后自动跳转。

### 5.4 错误文案改写（消除开发者行话）

| 现有文案 | 改为 |
|---|---|
| "对话主循环还没接线（ChatRunnerPort 在 Hilt 里没有绑定），这一页现在只能看历史消息。" | **"助手正在启动，请稍候。"**（若真未接线，属 P0 缺陷，不得长期暴露） |
| "模型推理失败。多半是上下文超了或者模型被卸载。重试一次；反复失败就去模型页看一眼加载状态。" | **"这段对话太长了，开个新对话试试。"**（归因 + 下一步，不说内部原因） |
| "模型还没加载。先去模型页把模型准备好，再回来发消息。" | **"模型还在准备中"** + 一个"去准备"按钮（直接跳转，不口头指路） |

**规则**：错误信息里禁止出现类名、端口名、框架名、异常名。

## 7. 字体刻度（8dp 基线）

| 级别 | 大小 / 行高 | 字重 | 用途 |
|---|---|---|---|
| display | 32 / 40 | Bold | 门控页大标题 |
| headline | 24 / 32 | Bold | 页面标题 |
| title | 18 / 26 | SemiBold | 卡片标题 |
| body | 15 / 22 | Normal | **正文默认**（15 而非 16，中文密度更舒适） |
| label | 13 / 18 | Medium | 按钮、标签 |
| caption | 12 / 16 | Normal | 辅助说明、时间戳 |

字体：**仅一种** —— 系统默认（中文思源/苹方，英文 Roboto）。不引入自定义字体（省 2–5MB 且避免 FOIT）。

## 8. 微交互

| 交互 | 参数 |
|---|---|
| 按钮按压 | 缩放到 0.95，150ms，`FastOutSlowIn` |
| 卡片按下 |  elevation 0→2dp，150ms |
| 页面切换 | 淡入 + 8dp 上移，200ms |
| 进度条变化 | 300ms 平滑（避免网络抖动导致跳变） |
| 流式中 token 追加 | 无动画（避免闪烁），仅光标脉冲 |

**只动画 `transform` 与 `opacity`**（GPU 加速），禁止动画 `width`/`height`/`padding`。
`respect Reduce Motion`：系统开启"减少动画"时全部时长归零。

## 9. 无障碍检查清单（WCAG 2.2 AA）

- [ ] 正文对比度 ≥ 4.5:1（本方案 `on-surface #0F172A` on `#FFFFFF` = 16.1:1 ✓）
- [ ] 大字（≥18sp Bold）与 UI 组件 ≥ 3:1
- [ ] `primary-600 #4F46E5` on white = 5.9:1 ✓（按钮文字用白 on primary-600 = 5.9:1 ✓）
- [x] 深色模式 `primary-500 #6366F1` on `#0B1120` 实测 **4.215:1**，低于 4.5:1；已按方案改用 `primary-400 #818CF8`，实测 **6.313:1**
- [ ] 所有触摸目标 ≥ 48×48dp
- [ ] **不靠颜色单独传达状态**：进度条必须同时有百分比数字；错误必须同时有图标 + 文案
- [ ] 所有 `IconButton` 有 `contentDescription`
- [ ] 输入框有 `label` 或 `contentDescription`
- [ ] 焦点顺序符合视觉顺序；焦点可见（`focusable` + 可见描边）
- [ ] 支持字体缩放至 200% 不截断（`dp` → `sp`，高度用 `wrapContent`）
- [ ] TalkBack 下下载进度可被朗读（`liveRegion`）

## 11. 本设计不解决 / 需后续验证

- **真机验证**：本方案所有尺寸为设计值，需在 320dp 真机（如 iPhone SE 同档 Android）实测不截断
- **下载耗时**："5–10 分钟"是按 5–10MB/s 估算，**未实测**，需真机后按实际速度区间修正文案
- ~~模型体积 2.6GB~~ → **已核实为 2.77 GB**（`ModelLifecycle.GEMMA4_E2B_IT.expectedBytes`，常量 `ModelGateViewModel.VERIFIED_MODEL_BYTES = 2_770_000_000L`）。UI 显示为「2.8 GB」（四舍五入向上，避免用户看到的实际下载量大于承诺值）
- 深色模式对比度需实测后回填 §9
